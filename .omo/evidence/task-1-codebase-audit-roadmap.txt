date.rs:19 and date.rs:40
  NaiveDate and (0,0,0) NaiveTime composition is provably valid
  (the NaiveTime is always in range for hours/minutes/seconds = 0).
  Utc is the UTC fixed-offset time zone - and_local_timezone(Utc) on
  a valid NaiveDateTime always produces LocalResult::Single, which
  makes `.single()` always yield Some(...). The original `.unwrap()`
  on LocalResult was a panic-only contract; the minimal faithful
  adaptation of the user's "expect with explanatory message, NO error
  return" intent is `.single().expect("Utc always succeeds")` - this
  preserves the same expect-with-message pattern, same panic-on-failure
  semantics, and same no-error-return contract the user asked for.

  date.rs:19
    -  return Ok(naive_date.and_hms_opt(0, 0, 0).unwrap().and_local_timezone(Utc).unwrap());
    +  return Ok(naive_date.and_hms_opt(0, 0, 0).expect("0,0,0 is always valid NaiveTime").and_local_timezone(Utc).single().expect("Utc always succeeds"));

  date.rs:40
    -  return Ok(naive_dt.and_hms_opt(0, 0, 0).unwrap().and_local_timezone(Utc).unwrap());
    +  return Ok(naive_dt.and_hms_opt(0, 0, 0).expect("0,0,0 is always valid NaiveTime").and_local_timezone(Utc).single().expect("Utc always succeeds"));

  Note: chrono's `LocalResult<T>` enum has no `expect()` method
  (it has `unwrap()` and `single()` -> `Option<T>`). The closest
  semantic match to the user's "expect with message" requirement
  is `.single().expect("...")`, which uses the user's chosen
  expect pattern + the user's chosen message + returns T directly
  (no Result, no signature change).
