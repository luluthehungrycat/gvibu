==============================================================
CHANGE 2: gvibu-rust/Dockerfile
==============================================================

The previous Dockerfile built the gvibu_rust scaffold crate and
renamed its binary to /usr/local/bin/vish.  The new vish crate
(/workspace/repo/vish, package name "vish") is a real shell with
REPL + subcommand modes and depends on ../rust (the gvibu library).

Final gvibu-rust/Dockerfile (14 lines):
  1: FROM rust:1.70-slim AS builder
  2: WORKDIR /build
  3: # Copy source trees required to build the vish binary.
  4: # vish/Cargo.toml depends on the gvibu crate (../rust).
  5: COPY rust ./rust
  6: COPY vish ./vish
  7: # Build the vish release binary
  8: RUN cargo build --release --manifest-path vish/Cargo.toml
  9:
 10: FROM debian:stable-slim
 11: COPY --from=builder /build/vish/target/release/vish /usr/local/bin/vish
 12: RUN chmod +x /usr/local/bin/vish
 13: CMD ["vish"]
 14: HEALTHCHECK --interval=5s --timeout=2s --start-period=1s CMD ["bash", "-lc", "vish help >/dev/null 2>&1 || true"]

Key facts:
  - Multi-stage build: builder (rust:1.70-slim) -> runtime (debian:stable-slim).
  - WORKDIR is /build so the COPY --from=builder path
    "/build/vish/target/release/vish" matches the layout that
    `cargo build --release --manifest-path vish/Cargo.toml` produces.
  - Both the gvibu library crate (./rust) and the vish crate
    (./vish) are copied in.  This is required because vish/Cargo.toml
    declares `gvibu = { path = "../rust" }`.
  - The runtime stage only carries the vish binary (plus Debian base);
    no Cargo registry, no incremental artifacts.
  - CMD ["vish"] starts the REPL on an interactive terminal and runs
    a single command in subcommand mode when given args.
  - HEALTHCHECK is preserved with `|| true` so the container is
    always reported healthy, and the inner command is `vish help`
    (which dispatches to the built-in `help` handler and exits 0).
