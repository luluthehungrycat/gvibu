File modified: /workspace/repo/rust/src/commands/mod.rs
- Added imports: `use std::collections::HashMap;` and `use std::sync::LazyLock;`
- Added `pub static COMMAND_MAP: LazyLock<HashMap<&'static str, &'static Command>>`
  initialized via `LazyLock::new(|| { COMMANDS.iter().flat_map(...).collect() })`
- Updated `pub fn lookup(name: &str) -> Option<&'static Command>` to use
  `COMMAND_MAP.get(name).copied()` (O(1) HashMap lookup).
- COMMANDS array left UNCHANGED (wasm-lib/src/lib.rs:67 still iterates it).

NOTE on spec deviation: the spec literal text for the LazyLock initializer
  `COMMANDS.iter().flat_map(|cmd| cmd.names.iter().map(|name| (*name, cmd))).collect()`
fails to compile with E0373 ("closure may outlive the current function, but it
borrows `cmd`, which is owned by the current function"). The compiler's exact
suggested fix was applied: added `move` to the inner `.map()` closure:
  `COMMANDS.iter().flat_map(|cmd| cmd.names.iter().map(move |name| (*name, cmd))).collect()`
This is the minimum change to make the LazyLock initializer compile. No other
behavioural deviation from the spec — signature, name, type, and semantics are
identical. The COMMANDS array is unchanged. No other files were modified.
